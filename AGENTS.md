# ConicIP.jl — guide for contributors and coding agents

Pure-Julia conic interior-point solver for quadratic programs with linear,
second-order cone, and semidefinite constraints. This file is the
tool-neutral working guide; `CLAUDE.md` imports it and adds only
Claude-specific conventions.

## Project Info

- GitHub: `MPF-Optimization-Laboratory/ConicIP.jl`
- Julia compat: `≥ 1.10` (CI runs 1.10, the current release, and nightly)
- Key deps: MathOptInterface, WoodburyMatrices, QDLDL, AMD
- Quadratic objectives are handled natively by both the direct `conicIP` API
  and the MOI wrapper (`ScalarQuadraticFunction` becomes `Q`; no SOC bridge)

## Architecture

- `src/ConicIP.jl` — main module: `conicIP` (equilibration wrapper) and
  `_conicIP` (the interior-point loop), types (`v4x1`, `VecCongurance`,
  `Solution`)
- `src/blockmatrices.jl` — block diagonal matrix type (`Block`)
- `src/kktsolvers.jl` — KKT routing (`choose_kktsolver`) and the dense /
  sparse / 2×2 solvers (`kktsolver_qr`, `kktsolver_sparse`,
  `kktsolver_2x2`, `pivot`)
- `src/kktsolver_ldl.jl` — sparse quasidefinite LDLᵀ (`kktsolver_ldl`)
- `src/schur.jl` — PSD-variable Schur solver (`kktsolver_sdpschur`)
- `src/correctors.jl` — Gondzio centrality correctors
- `src/equilibrate.jl` — Ruiz scaling and postsolve checks
- `src/certificates.jl`, `src/fallback.jl` — infeasibility certificates
- `src/preprocessor.jl` — presolve (`preprocess_conicIP`, `imcols`)
- `src/MOI_wrapper.jl` — MathOptInterface wrapper (`Optimizer`)
- `src/timing.jl` — opt-in per-phase timing (`PhaseTimes`)
- `src/logging.jl` — the iteration log (all printing happens here)
- `src/trace.jl` — the structured trace (`SolverTrace`, JSON Lines)

## Key Design Patterns

- The solver accepts `c`, `b`, `d` as vectors (`AbstractVector`)
- Cone dimensions are specified as `[("R", n), ("Q", m), ("S", k)]` tuples
- Block diagonal matrices (`Block`) hold per-cone scaling matrices
  (Diagonal, SymWoodbury, VecCongurance)
- Nesterov-Todd scaling is computed per cone block
- `Id(n)` creates an n×n identity as `Diagonal(ones(n))`
- `v4x1` struct fields alias the vectors passed in (no copy), so buffer reuse
  requires lifetime analysis
- Local closures `÷(x,y)` and `∘(x,y)` are cone group division/product; the
  in-place variants are `cone_div!`/`cone_prod!`
- Julia gotcha: Unicode operators (`÷`, `∘`) cannot have `!` appended
  (`÷!` is a parse error)
- `_conicIP` is one large function whose closures capture its locals. A
  local assigned in more than one place (or inside a closure and outside
  it) is boxed, which costs an allocation per access and type stability.
  Keep captured variables single-assignment; put mutable per-iteration
  state in a struct field (see `IterStats`).

## Observability: seeing what the solver does

Four layers, from human-readable to machine-readable. All are off or cheap
by default.

| I want to… | Use |
|---|---|
| watch a solve | `verbose = true` (default for `conicIP`; MOI: `"verbose" => true`) |
| choose the look | `log_style = :rich` / `:classic` / `:auto`; `ENV["CONICIP_LOG_STYLE"]`; `NO_COLOR` |
| send the log elsewhere | `log_io = io` (MOI: `"log_io"`) |
| get the iteration history as data | `trace = SolverTrace()`, `trace = rec -> …`, `trace = "run.jsonl"` (MOI: `"trace"`) |
| trace every solve, even through JuMP | `ENV["CONICIP_TRACE"] = "run.jsonl"` (appends) |
| see rare internal events | `ENV["JULIA_DEBUG"] = "ConicIP"` (`@debug` with `_group`s below) |
| know where time and memory go | `timing = ConicIP.PhaseTimes()`; `ConicIP.phase_table(pt)`; `benchmark/profile.jl` |
| KKT regularization totals | `sol.kkt_repaired`, `sol.kkt_refactors`, `sol.kkt_solves` |
| type-aware static analysis | `~/.julia/bin/jetls check --quiet --progress=none src/ConicIP.jl` |

### The log

`:classic` is the fixed-width ASCII table; `:rich` is a Unicode table
(green residuals once below `optTol`, a progress bar toward `optTol`, a
`gap` column, an exit card with sparklines). `:auto` gives rich only when
`log_io` is a TTY, so tests, Documenter, CI and pipes stay classic. The last
line printed is the status the caller receives: if postsolve overturns the
solver's verdict, classic prints `POSTSOLVE -- status changed: A → B` and
rich titles the card `A → B`.

### The trace (schema `conicip-trace/1`)

One `NamedTuple` per event, each with `event`, `depth` (0 = top-level solve)
and `t` (seconds since the call started). Full field list: the
`SolverTrace` docstring (`src/trace.jl`). The fields that matter most:

| event | fields |
|---|---|
| `header` | sizes `n m p`, `cones`, `kktsolver` (+ `routed`), tolerances |
| `iter` | `rPr rDu rCp rEq rGap rPrRow rEqRow` (stopping test; `optMeasure` is their max), `pobj dobj mu`, `icertp icertd` (infeasibility screens; NaN = sign test failed), `alpha sigma` (step that produced this iterate), `refine rnorm` (refinement count, relative KKT residual), `kkt_repaired kkt_refactors` (-1 = no diagnostics), `cc_acc cc_try` (-1 = off), `kkt_solves`, `best` |
| `note` | `source` (`:presolve :equilibrate :stall :fallback`), `msg` |
| `exit` | `kind`, `status`, `detail` — how the loop ended |
| `final` | the returned `status`, `message`, residuals, `changed_from`, `phases` |

The optimality test is `optMeasure < optTol && max(rPrRow, rEqRow) < optTol`.
In JSON, NaN and ±Inf are `null`. A quick look at a trace file:

```
jq -c 'select(.event=="iter") | [.iter, .rPr, .rDu, .rCp, .rGap, .alpha, .rnorm]' run.jsonl
jq -c 'select(.event=="final")' run.jsonl
```

or in Julia: `using JSON; recs = JSON.parse.(eachline("run.jsonl"))`.

### Debug groups (`JULIA_DEBUG=ConicIP`)

| `_group` | event |
|---|---|
| `:routing` | the KKT solver choice and the cost estimates behind it |
| `:kkt` | LDLᵀ pivots replaced by dynamic regularization; static shifts bumped; sdpschur falling back to dense QR |
| `:refine` | a refinement correction rolled back; budget spent above tolerance |
| `:linesearch` | the interiority back-off halved the step |
| `:certificate` | a ray nominated by a screen, with the validator's verdict (`farkas_residual`, `separation`, `cone_margin`); the post-loop re-screen |
| `:postsolve` | a certificate or an optimal point rejected on the original data |

### Recipes

- **`:Abandoned` or a stall.** The rich card's `best` line marks the
  residual(s) still above `optTol` in red. In the trace, look at `alpha`
  (steps collapsing toward 0 → stall; `note` with `source = :stall`), at
  `rnorm` (inaccurate KKT steps), and at `mu`. `JULIA_DEBUG` groups
  `:linesearch` and `:refine` show back-offs and refinement roll-backs.
  Remedies to try: `staticReg = 1e-8`, another `kktsolver`, `preprocess_conicIP`.
- **"Every column is below tolerance but it keeps iterating."** Two stopping
  tests are not in the classic table: the relative gap (`rGap`, rich `gap`
  column) and the row-wise feasibility tests (`rPrRow`, `rEqRow`; the rich
  progress cell shows `rows …` in that case). Check them in the trace.
- **Red rows / `!` in `ref`.** The step's relative KKT residual (`rnorm`)
  is above `1e-3` after refinement: the KKT system is ill-conditioned. Check
  `kkt_repaired` and `JULIA_DEBUG` group `:kkt`; try `staticReg` or a
  different `kktsolver`.
- **A certificate that is not claimed.** Follow `icertp`/`icertd` in the
  trace; group `:certificate` shows each nomination and why the validator
  rejected it; `note`s with `source = :fallback` show the auxiliary solves.
- **Slow solves.** `timing = PhaseTimes()` (the rich card then shows the
  phase shares), or `benchmark/profile.jl`.
- **Did my change alter the trajectory?** Run the same script with
  `CONICIP_TRACE` set on both branches (e.g. a worktree in `.worktrees/`)
  and diff the `iter` records with the `jq` line above.

### Contributor invariants

- Solver code never prints. Emit an event instead
  (`log.on && _log_note!(log, :source, msg)` and friends in
  `src/logging.jl`); the renderers and the trace pick it up.
- With the log off, a solve must not allocate more or box new variables:
  compare `PhaseTimes` `b_*` fields before and after, and check that no new
  local of `_conicIP` appears as a `Core.Box` in the lowered code of its
  keyword body (or run JETLS, which reports boxed captures).
- The classic table is pinned by `test/golden/*.txt` (numbers masked). An
  intended change: rerun with `CONICIP_UPDATE_GOLDEN=1` and review the diff.
- Trace fields may be added freely; when one changes meaning or is removed,
  bump `TRACE_SCHEMA` and update the `SolverTrace` docstring.
- `@debug` only on cold paths, always with a `_group`; never `@info`/`@warn`
  in the solve path (they would bypass `verbose` and `MOI.Silent`).

## Static Analysis

- Type-aware diagnostics: `~/.julia/bin/jetls check --quiet --progress=none src/ConicIP.jl`
  (JETLS CLI; analyzes the whole package via includes, ~10 s warm)
- `--show-severity=warn` for inference errors only; the default also shows
  lowering hints (unused locals, boxed captures)
- Treat findings as leads, not verdicts: JET diagnostics on dynamic code have
  false positives

## Environment

Julia is installed with juliaup (`curl -fsSL https://install.julialang.org | sh -s -- --yes`;
add `juliaup add 1.10` for the compat floor). Cloud containers do not have it
preinstalled; a setup script that installs it and warms the package caches:

```bash
#!/bin/bash
set -euo pipefail
if ! command -v juliaup >/dev/null 2>&1 && [ ! -x "$HOME/.juliaup/bin/juliaup" ]; then
  curl -fsSL https://install.julialang.org | sh -s -- --yes --default-channel release
fi
export PATH="$HOME/.juliaup/bin:$PATH"
juliaup add 1.10 || true
ln -sf "$HOME/.juliaup/bin/julia"   /usr/local/bin/julia
ln -sf "$HOME/.juliaup/bin/juliaup" /usr/local/bin/juliaup
REPO="${REPO:-/home/user/ConicIP.jl}"
if [ -f "$REPO/Project.toml" ]; then
  cd "$REPO"
  julia --project -e 'using Pkg; Pkg.instantiate(); Pkg.precompile()' || true
  # test deps, in a throwaway environment (leaves test/Project.toml alone)
  julia -e 'using Pkg; Pkg.activate(temp=true); Pkg.develop(path=".");
            Pkg.add(["JSON", "MathOptInterface", "Dualization"]); Pkg.precompile()' || true
fi
```
